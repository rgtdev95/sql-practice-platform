# MVP scope: core loop + hints/solutions

## Decision

v1 ships: Django auth (signup/login/logout), a problem catalog (title,
difficulty, prompt, schema), a SQL query editor page, run-query with
correct/incorrect feedback, per-user solved/unsolved tracking, a hint field,
and a reveal-solution action per problem.

## Alternatives considered

- **Bare core loop** (no hints/solutions): less content to author up front,
  but a first-time user who gets stuck has no way forward. Rejected —
  hints/solutions are cheap to add (just two more text fields on `Problem`
  and two UI affordances) and materially change whether the product is
  usable solo.

- **Core loop + gamification** (streaks, points, leaderboard): deferred.
  Engagement features are premature before the core practice loop exists
  and has real users; adding a `Score`/leaderboard model now would be
  built against unvalidated assumptions about what motivates users here.
  Revisit once the core loop is live.

## Consequence

`Problem` gets `hint` (nullable) and `solution_sql` fields from the start.
No `Score`, `Streak`, or `Leaderboard` models in v1 — add them later if
engagement data shows they're needed.
